# Supabase 数据库草案

`migrations/202611180001_initial_schema.sql` 是 BLACK GOLD 的初始数据库设计草案，包含个人资料、健康记录、双人关系、共享授权、AI 对话、提醒和私有照片储存等结构。

## 本次安全加固

- 使用安全的数据库函数检查双人关系，避免 couples / couple_members 的 RLS 递归。
- 新用户注册时自动建立自己的 profiles 记录。
- 双人邀请使用随机令牌；数据库只保存令牌的 SHA-256 摘要，邀请默认 7 天过期。
- 提供建立双人关系、创建邀请、接受邀请、撤销未接受邀请的受控函数。
- 每个健康资料类别必须由资料拥有者主动授权；授权可逐项撤销。
- 建立私有的 `health-private` Storage bucket；对象路径必须以当前用户 UUID 为第一层目录。
- 不开放客户端直接修改邀请、共享授权或系统发布管理表。

## 重要：尚未部署

这份 SQL **尚未在你的 Supabase 项目执行，也没有经过真实数据库运行测试或独立安全审计**。目前只是经过代码层面的设计修正，不能视为生产环境已安全。

下一步必须在独立的 Supabase 测试项目执行，并验证：
1. 新用户注册后是否自动建立 profile。
2. 两个不同账号能否建立关系、邀请、接受邀请和撤销邀请。
3. 未获授权的账号无法读取对方任何健康记录。
4. 逐项授权后只能读取获授权类别；撤销后立即失去读取权限。
5. 用户只能读取、写入和删除自己 Storage 文件。
6. 已有项目或已有 Storage policies 不会留下更宽松的访问规则。

不要把 Service Role / Secret Key、数据库密码或用户健康数据放进 GitHub。客户端只使用 Publishable Key，并且所有健康数据表必须继续由 RLS 保护。
